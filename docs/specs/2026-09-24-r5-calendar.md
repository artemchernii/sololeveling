# R5 — Calendar

**Done when** (PLAN.md §4): a gym session is dragged from 8:00 to 9:15 and asks nothing.

Today the week grid is click-to-open only. Every change of time goes through
`EventDialog`, and that dialog speaks in "start + minutes". R5 makes the grid
itself the editor for time, and makes the dialog speak start–end.

## What gets built

1. **Drag to move.** Grab a block, drop it anywhere in the week — another hour,
   another day. Snaps to 15 minutes. Drops write straight away: no dialog, no
   confirm. The block settles with `motion-pop` so the write is seen to land.
   Works for events (`events.update`) and scheduled tasks (`tasks.setSchedule`).
   Milestones stay unmovable — a due day is read, not booked.
2. **Drag to resize.** The bottom edge of a block is a handle; pull it to any
   length, 15-minute snap, 15 minutes minimum. This is "any duration".
3. **Start–end instead of minutes.** `EventDialog` swaps the minutes field for
   an end time. Stored shape does not change: events already store
   `startsAt`/`endsAt`; tasks keep `durationMin` and the UI converts.
4. **Binding.** An event can belong to a project (field exists, no UI yet) and
   to a goal (new optional `events.goalId`). Two pickers in the dialog. The
   block shows its project's name in small mono under the time.
5. **Reminders.** See question 3 — this is the one piece that might be deferred.
6. **Pointer events, not a library.** Drag is ~150 lines of `pointerdown/move/up`
   in a hook; that also covers touch. No new dependency.

## Files

- `src/lib/calendarDrag.ts` (+ test) — pure maths: pixel → snapped time, move
  and resize results, clamping to the grid. All the logic worth testing.
- `src/components/calendar/WeekGrid.tsx` — handles, ghost while dragging, drop.
- `src/components/calendar/EventDialog.tsx` — end time, project and goal pickers.
- `src/routes/_app/calendar.tsx` — wires drops to the two mutations.
- `convex/schema.ts`, `convex/events.ts` (+ tests) — `goalId`, owner check on
  the bound project and goal (another owner's id is refused).

## Open questions — each with my recommendation

1. **Dragging one Tuesday of a weekly series.** An occurrence has no row of its
   own (§3b.6), so today the only thing that can move is the whole series.
   **Recommend:** a drag moves the whole series by the same amount, and a small
   "moved every Tuesday · Undo" line appears for five seconds. Per-occurrence
   exceptions are a real feature of their own; not in this row.
2. **Undo after any drag.** "Asks nothing" means no confirm, but a mis-drop
   should be one tap to reverse. **Recommend:** yes, the same five-second Undo
   line for every drag.
3. **Reminders.** PLAN parks notifications (the bell) under Late, and a real
   push to a closed phone needs a service worker and web-push keys.
   **Recommend:** a per-event "remind me N min before" stored on the row, and a
   browser notification fired while any tab of the app is open. No push to a
   closed app in R5 — that goes with the bell.
4. **Binding shows where?** **Recommend:** only on the calendar block and in the
   dialog for now. Project and goal pages listing their upcoming events can come
   later if you miss it.
5. **Phone.** Seven columns at 375px is already tight. **Recommend:** drag works
   there too (press-and-hold 300ms to pick up, so scrolling still scrolls), and
   no separate day view in this row.
