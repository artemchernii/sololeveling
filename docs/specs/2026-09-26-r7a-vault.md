# R7a — the Vault: class sheets, read once (26 Sep)

Artem: "I have sometimes pages (pdf) with what we learned in class or
homework … store it and attach to class I had, and a tool that will analyze
what is inside and make a summary + conclusion." The sheets are **mostly
scanned**. This is the first slice of R7: the one path the app will use to
call a model, finances and the helper included, built for one real job.

## What gets built

- **Vault, a fourth Languages tab** (Today · Learn · History · Vault): the
  language's documents, newest first. Each card shows the file name, its
  session ("Class · Fri 26 Sep") or "not linked", and what the model read:
  **summary**, **conclusion**, **new words** (Portuguese → English), and
  the **full text**, folded, with Copy. Tap to open the scan itself.
- **Adding one:** "+ Add document" in the Vault takes a PDF or photo
  (JPG/PNG/WebP; an iPhone hands the browser a JPG, not HEIC) and asks
  which session it belongs to. It suggests today's
  class, then the latest session, or "not linked". The same paperclip
  is on each session row in History's day list.
- **Read once, when attached.** A background Convex action sends the file to
  **Claude Haiku 4.5**, which reads scans and photos directly. One call
  returns the text, summary, conclusion and new words as structured
  JSON. Stored, never sent again. The card shows _reading…_, then the result
  with its attribution ("read by Claude Haiku 4.5 · 26 Sep, 18:40"), or
  _couldn't read — retry_.
- **One AI path, provider as a setting.** `convex/ai/` holds a `read`
  (documents → Claude) and, when R7 chat comes, a `chat` (text → DeepSeek).
  Keys live in Convex environment variables only; nothing model-related
  reaches the browser.
- **A budget the app enforces:** at most **30 readings a month** and
  **10 MB per file**. The 31st is refused with a message saying why and
  when it resets (a count of rows in `readings`, a sanctioned source). No
  cost figure is shown anywhere: there is nothing real to put on it.

## Reality rules this keeps

What the model writes is **text, never a number on screen**. It is stored,
attributed to a named model, and timestamped: the same conditions §1 sets
for an external reading. It never marks a path topic as learned or a
session as done. Suggesting path topics from a sheet is a later slice, and
one tap from you would still be the proof.

## Data

- `attachments` gains `logId: v.optional(v.id('logs'))` and `area:
v.optional(areaSlug)` (the parent of a "not linked" sheet), plus
  `by_owner_log` and `by_owner_area` indexes. One parent each, as now.
- New table **`readings`**: `ownerId`, `attachmentId`, `status`
  (`reading` / `done` / `failed`), `text`, `summary`, `conclusion`, `words`
  (array of `{ pt, en }`), `model`, `readAt`, `inputTokens`, `outputTokens`,
  `error?`. Indexes `by_owner_attachment`, `by_owner_time` (for the monthly
  count).

## Files

`convex/schema.ts`, `convex/attachments.ts` (log/area parents, remove takes
its reading), `convex/readings.ts` (queries, the internal write, retry,
the cap), `convex/ai/read.ts` (`"use node"` action, Anthropic SDK),
`src/lib/reading.ts` (parse and validate the model's JSON),
`src/components/languages/Vault.tsx`, `LanguagePanel.tsx` (the tab),
History's day rows (the paperclip). New dependency:
**`@anthropic-ai/sdk`**, to send scans to the one model that reads them.

## Tests

`convex-test`: attach to a log and to an area; refused on another owner's
log; the 31st reading refused; removing an attachment removes its reading;
retry only on `failed`. `src/lib/reading.test.ts`: good JSON parses, a
missing field or wrong type is a `failed` reading, not a crash. The
external call itself is checked by hand with one real scan. It costs
about 2¢, and I ask before running it.

## Done when

A scanned class sheet attached to today's class shows its full text, a
summary, a conclusion and its new words within a minute, labelled with the
model and time. It is listed in the Vault and reachable from that day in
History. Typecheck, lint, format, tests and build green.
