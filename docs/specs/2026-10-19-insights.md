## The room

`room: 'insights'` beside overview / flow / portfolio in
`src/routes/_app/finances.tsx` (loads the first time it is opened, like
the others). Four numbered bands under a hero:

- **Hero** — `[ MARKET READ · OCT ]`, the headline (mood word coloured),
  two plain sentences, four numbers; right: model, time, tokens, cost,
  `⚡ PRO PLAN · NO CREDITS` or `💳 API CREDITS`, READ MARKET / READ AGAIN.
  A 4px mood edge on the left (good, warn for mixed, danger for failed).
- **1 THE MARKET** — four rate cards (US inflation, euro inflation, Fed,
  ECB, next meeting as a badge); MARKETS (8 cards: S&P 500, Nasdaq 100,
  MSCI World, STOXX 600, gold, bitcoin, EUR/USD, US 10Y) with a
  1D · 1W · 1M · 1Y switch; the S&P 500 heatmap (30 biggest by sector,
  logos, a white dot on held ones) and the regions strip.
- **2 WHAT IT MEANS** — the read's lines; HOW IT IS MADE (feeds, the six
  kinds, the fixed shape).
- **3 MINE** — positions heatmap (box = euros, colour = the period, the
  Portfolio verdict on each, ADD / HOLD / WAIT explained underneath);
  ALLOCATION (tech · US · Europe · health · gold, mine against MSCI World,
  ETFs opened up) with the read's opinion.
- **4 NEXT** — 2–4 idea cards; ASK.

ⓘ cards everywhere a term appears (what it is · why it moves the money ·
now). Logos by `src/lib/logo.ts`, emoji by `src/lib/tags.ts`.

## Builds (one branch and PR each, in order)

### I1 — the room and THE MARKET (no model)

- `convex/insightsMarket.ts`: one action `market({ period })` returning
  rates, the 8 markets, the 30 companies and 5 regions with their change
  over the period, each with its source and fetched-at. Yahoo chart API
  (as the app's price fetch already calls it), BLS and Eurostat for
  inflation, ECB for its rate, FRED for the Fed rate. Writes nothing.
  On the test backend (E2E=1) a canned answer.
- `src/components/finances/insights/*` — Hero (not read only in I1),
  RateCards, Markets, SectorMap. The page calls the action once on open
  and once per period not yet seen, keeps answers in memory 10 minutes.
- Scenarios: S1 open → four rate cards, 8 markets, heatmap, all with
  source and time; S2 1D/1W/1Y each changes the numbers and the
  "vs" line; S3 a source not reached → that card says NOT REACHED, the
  rest stand; S4 ⓘ opens its card; S5 phone width, no sideways scroll;
  S6 (unit) the action writes no row.

### I2 — MINE

- Positions heatmap from Portfolio's own positions and `verdict()`; the
  period change from I1's fetch. Allocation: each ETF's top holdings and
  sector/country split fetched on open (Yahoo), the world from IWDA's.
- Scenarios: S1 every position a box sized by euros, with its verdict;
  S2 a frozen one striped, FROZEN; S3 allocation bars mine · world with
  both numbers; S4 no positions → the empty state.

### I3 — the read and the ideas

- `marketReads` table, one per month (like `weekReads`): facts stored
  with the read, status reading/done/failed, verdict words, lines
  `{kind, badge, title, line, factKeys[], plain}`, ideas
  `{ticker, why, bull, bear, wrong}`, sources `{site, title, url, day}`,
  model, tokens, cost, paidBy.
- `convex/ai/market.ts` — Sonnet 5.5 with web search, JSON schema output;
  checks the month's spend before calling and adds the response's cost
  after (`aiSpend` per month), refuses at $2 with CAP REACHED.
- Localhost: a Start server function runs `claude -p` with the same
  prompt and schema on his Mac and hands the answer to the same `finish`;
  paidBy `pro`. Deployed: the API; paidBy `api`.
- Idea cards: the app fetches each named ticker's price, month line and
  signals on open; a ticker it cannot find is dropped, not shown.
- Scenarios: S1 READ MARKET → reading → read: headline, 3–5 lines with
  kind icons, facts, sources; S2 a mixed month with a NO DATA line;
  S3 failed → nothing paid, the last read stays; S4 cap reached → button
  off, NEXT 1 NOV; S5 reload shows the stored read; S6 (unit) a line
  naming a fact key not given is refused; S7 (unit) spend adds up and
  stops at $2.

### I4 — ASK

- Thread on the page only; a question sends the facts and the read;
  🌐 per question; each answer shows its model and cost and counts
  against the same cap. Suggested questions from the read.
- Scenarios: S1 ask → typing → answer with facts; S2 🌐 → sources;
  S3 cap reached → input off; S4 reload → thread empty.

## Cost

- Convex: I1, I2, I4 write nothing; one action call per open (and per
  new period). I3 adds one row a month (~10 KB) and a spend counter.
- Anthropic: about $0.24 a read (Sonnet 5.5, ~8 searches, ~62K in, ~3K
  out) and $0.002–0.07 a question, only on deployed, stopped at $2 a
  month; localhost uses his Pro plan. His Console limit (e.g. $5) is the
  ceiling.
